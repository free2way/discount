# 与 freebie-radar 的产品对照

对照基准：[ZiChuanLan/freebie-radar](https://github.com/ZiChuanLan/freebie-radar)，审阅日期 2026-11-15。

## 值得吸收的能力

| 方向 | freebie-radar 的做法 | GLOBAL DEAL HUNTER 的取舍 |
| --- | --- | --- |
| 信息流 | 用 `kind × category × obtain` 拆分福利、好价、开源、资讯与噪音 | 保持优惠专注度，下一阶段补齐“真正免费 / 有条件 / 抽奖 / 试用 / 推广 / 付费”获取方式 |
| 扫描 | 每个源独立周期、运行记录、启停与重跑 | GitHub Actions 每 2 小时统一扫描；前端公开健康度、耗时、重试和连续失败，不把密钥放到浏览器 |
| 去重 | 标题与事件聚类，多源报道折叠 | 已有 canonical key 去重；下一阶段增加“同一优惠多源佐证”视图，反向提升可信度 |
| 质量 | 规则初筛、AI 语义审核、屏蔽词前置 | 当前坚持官方回溯、候选审核和风险提示；后续优先增加获取方式分类与用户屏蔽规则，而不是扩大无关资讯 |
| 推送 | Telegram 多路由、静默时段、即时/批量 | 当前浏览器收藏与截止提醒；推送路由适合在持久化后端和鉴权完成后建设 |
| 前端 | 高密度表格、多个信息频道、紧凑/双列/三列视图 | 保留更克制的决策界面，突出价值、地区、资格、隐藏条件、截止日期和验证状态 |
| 运维 | 独立数据源运维、运行历史、质量与保留策略 | 新增数据源中心；先提供透明诊断和本地信息流偏好，扫描启停仍以仓库配置和 GitHub Actions 为准 |

## 我们应该形成的差异化

1. **优惠可信度而不是内容数量**：社区帖子只作为线索；官方活动页、地区、资格和隐藏条件决定是否验证通过。
2. **真实可得价值**：金额、免费期、所需充值/交易量/邀请条件应共同进入价值评分，避免把“高门槛大数字”排在最前。
3. **活动生命周期**：开始、截止、最后验证、即将结束、过期归档是一条完整状态链。
4. **来源透明度**：每个源公开显示接入方式、密钥边界、响应耗时、重试和失败历史。
5. **多源佐证**：同一优惠被官方、社区和聚合站同时发现时，合并为事件并展示证据链，而不是重复推送。
6. **个人情报策略**：重点来源优先、隐藏来源、地区与资格过滤、收藏及变化提醒共同形成个人工作台。

## 本轮已经落地

- 数据源中心覆盖固定源和小红书可选连接器。
- 按中文社区、官方平台、软件与优惠、社交线索、产品发现分组。
- 展示最近状态、本轮条目、响应耗时、尝试次数、连续失败和最近成功时间。
- 展示采集格式、可信层级、密钥/登录态要求和来源说明。
- 支持把来源设为“重点”，其优惠在本设备的信息流中优先展示。
- 支持把来源从本设备的信息流隐藏，不影响 GitHub Actions 扫描。
- 提供 GitHub Actions 扫描入口；密钥继续只存在于 GitHub Secrets。

## 后续优先级

1. 获取方式六级分类与筛选。
2. 同一优惠的跨源证据链、冲突检测和可信度解释。
3. 热点趋势与“突然升温”信号，但只统计优惠域内容。
4. 持久化管理后端、管理员鉴权和真正的源启停/周期配置。
5. Telegram/邮件/Web Push 多路由推送及静默时段。
